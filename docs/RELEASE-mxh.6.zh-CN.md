# MXH Route 1.14.0-mxh.6

## 本次变化

- `US-West Entry` 固定优先级：DMIT → VMISS → MoeCloud；同一服务商内沿用原 IPv4／IPv6 顺序。
- 三个独立 HTTPS 目标检测节点，当前节点连续三轮失败且备用连续两轮可用才切换。首选至少三轮正常并稳定两分钟后切回；休眠造成的长采样空档不计入稳定期。
- 手动选择暂停自动切换，重新启动代理后恢复。全部节点不可用时不切 DIRECT，不通过修改其他业务组实现切换。
- 添加滚动核心日志，记录缓冲区重置、应用退出、服务重载和节点切换边界；探针日志记录每个节点结果及当轮选中节点。
- 核心日志和健康日志各最多保留约 60 MiB（当前文件加五份备份）。日志含诊断所需的域名、地址和节点名称，应留在本地。

## 验证

- 桌面侧 42 项自动测试通过，包含新增的故障切换、恢复防抖、手动选择、休眠间隔、探针路由与日志轮转测试。
- Dashboard 43 项测试通过；类型检查、ESLint、Stylelint、安装器预检查通过。
- 使用现有权威配置生成的系统代理与 TUN 运行配置，都通过 sing-box 1.14.0 配置检查；每种模式有五个独立节点探测入口。
- 未人为断开真实 DMIT／VMISS／Moe 服务来测试切换，尚未进行已安装 GUI 的长时间故障恢复验收。

## 安装后

覆盖安装后重新打开应用，并重新启动一次代理。只有新版运行配置建立完成后，独立节点探测和自动切换才会启用；原权威文件不需要添加私有扩展字段。

保持应用运行或留在托盘。当前实现由桌面进程保存核心日志并执行优先级监测；退出桌面应用时不会继续监测，也不能保证补录退出期间的核心日志。

自动切换主要作用于新连接，不保证已有连接无缝迁移。此版本补充的是故障切换和诊断能力，不能据此认定已经修复此前所有“重启后恢复”的根因。
