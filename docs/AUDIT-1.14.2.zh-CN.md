# MXH Route 1.14.2 定制审计与收敛（2026-09-26）

## 范围与版本

对照官方 `SagerNet/sing-box` 的 `v1.14.2`、官方桌面端与 Dashboard 的相应 `main` 提交，检查 MXH Route 的桌面端、Dashboard、内核三棵源码。升级前分别建立了 `backup/pre-1.14.2-20260925` 本地分支。源码升级不等于安装或发布；本轮不替换正在运行的客户端，不改变用户代理开关、私有配置或服务器。

官方 1.14.2 包含启动时网络重置、Windows 已关闭连接错误识别和 selector 等修复，可能改善一部分网络变化后的行为；它没有代替本项目的系统代理归属判断。官方发布页：<https://github.com/SagerNet/sing-box/releases/tag/v1.14.2>。

## 定制分类

| 类别 | 内容 | 结论 |
|---|---|---|
| 必要 | MXH Route 独立应用、服务、管道、注册表和数据目录；签名验证与独立更新通道 | 保留，防止覆盖官方客户端或接收错误安装包 |
| 必要 | 路由/流量捕获模式控制、配置驱动的入口故障切换及图形设置 | 保留用户选择；不恢复服务商名称硬编码 |
| 必要 | 大配置 RPC 上限、核心与健康日志归档、公开规则集首次导入缓存 | 保留兼容性与诊断能力；缓存只含公开规则，不写入私有配置 |
| 可收敛 | 入口独立探针与整体代理探针都访问相同的三个 HTTPS 目标 | 两者分别验证候选节点和实际链路，并非可直接删除的重复功能；统一证据与恢复边界，避免互相让位造成盲区 |
| 可收敛 | 自动重载 | 仅在整体链路连续失败、没有应由入口切换解决的单节点故障时执行一次；所有入口新近确认均不可达时允许一次受控恢复 |
| 冗余但无运行风险 | 历史版本说明中的固定 DMIT/VMISS/Moe 排序和旧日志容量 | 仅保留为历史记录；当前行为以配置和本文件为准 |
| 冲突 | Windows 代理注册表显示已关闭，但本地 CONNECT 仍成功，健康守护误判正常；内核只缓存自身“已启用”状态 | 分开判断系统代理所有权与本地代理质量，并允许显式重新应用 |
| 冲突 | 官方 Dashboard 1.14.2 始终显示更新轨道，MXH Route 私有发布通道实际仅使用 beta 轨道 | 官方构建继续显示轨道；MXH Route 隐藏不可生效的轨道选择 |

## 本轮收敛策略

1. Windows 系统代理地址、开关、PAC/自动发现只读核实。若代理地址已变更，或启用 PAC/自动发现，不抢占；仅在地址仍完整匹配本应用、开关关闭且代理确实运行时，连续两次确认后自动重新应用一次。
2. 恢复通过原 daemon 的用户会话执行，不重启 sing-box，不先清空代理设置。恢复前在串行操作队列中再次核对配置、模式、服务、选择和注册表；完成后复核注册表。再次被关闭就暂停自动重试并发 Windows 通知，同时写入健康日志；手动重新启动代理才重置此限额。
3. 入口节点探测仍优先处理单节点故障。若一轮独立探测确认全部候选都不可达，且整体代理也连续失败，允许一次整体重载；重载前再次核对证据。这样不会因“所有候选都失败”而永久让位，也不会在有健康备用时盲目重载。
4. 保留原有操作代数、观察窗和分组选择快照，防止手动切换、入口自动切换、系统代理恢复及整体重载同时改动运行状态。

## 验证和限制

- 桌面端类型检查、Electron/Vite 生产构建、Dashboard 类型检查、单测与 lint、安装器预检，以及关键 Go 包测试和完整 Windows daemon 构建需通过后才可打包发布。
- 本轮不做真实断网、注册表故障注入或安装覆盖测试；这些仍需在用户安排的维护窗口验证。
- Windows 注册表摘要不是所有 WinINET 连接选项的完整所有权证明。其他程序进入 TUN 模式但仅关闭开关且保留本应用地址时，仍可能与一次自动恢复相遇；一次之后会停止争夺并告警。不能保证识别是谁修改了设置。
- 若 Windows 通知被系统禁用，告警仍会保存在健康日志中。
