# 守护机制修订（2026-09-27，未发布源码）

本次修订基于 1.14.2-mxh.1；源码修复、构建通过不代表用户已安装，也不代表完成真实 Windows 会话验收。未修改用户配置、系统代理开关、服务器或 Clash。

## 本地系统代理

- 独立轻量循环：正常每次完成后约 2 秒读取一次；检测到匹配本应用的已关闭开关后约 1 秒复核。无需等待 HTTPS 探测或节点切换后的 30 秒网络观察窗。
- 读取由 Electron 主进程的用户会话执行，不能用工具沙盒 HKCU 读取替代宿主用户事实。现阶段是注册表摘要，不宣称覆盖所有 WinINET 连接选项。
- 写操作仍在同一服务操作队列执行，执行前核对服务、配置、模式、用户操作意图和代理归属。用户停止操作会立即作废排队修复，停止本身也串行执行。
- 正常地址匹配才恢复；地址为空、其他地址、PAC 或自动检测配置均避让。不同网站访问成功不能证明 Windows 已启用代理。
- 自动恢复额度及不确定状态保存到应用设置。分组切换、配置刷新、自动重载、探测过期、仅重启应用都不恢复额度。用户明确启动代理或点击受限的“重新核对并恢复”才重新授权；后者也不能覆盖其他代理。
- 恢复 RPC 使用 3 秒传输截止时间。daemon 把取消上下文传到 Windows 设置锁内，过期且尚未执行的写入不再执行。已经进入 OS 调用的写入不能保证撤回，因此超时保持“结果不明”，继续读取但不自动再次写入，直至用户明确重启代理。
- 概述的流量捕获卡片新增 Windows 实际状态摘要，与选择的模式分开。显示正常、复核、恢复、避让、暂停或未知；避让和重复关闭有去重系统通知，通知关闭不影响页面提示。

2–5 秒是正常调度条件下的恢复目标，不是实测保证；注册表读取、服务操作排队、worker 启动和 RPC 超时都可能增加耗时。系统代理恢复只应用开关，不重启内核。

## 节点探测

- 当前入口独占一条探测通道；失败后下一次约 1 秒复核，达到配置阈值后使用故障间隔。无需等全部候选完成。
- 备用巡检最多两个节点并行，每个节点仍为三个 TLS 校验的 HTTPS HEAD，至少两个成功才算可用。另有至多一个切换目标的即时复核。不是测速，不采集浏览记录。
- 当前入口健康时，未使用备用（例如不可达 IPv6）不会导致当前入口持续加快巡检。
- 仅实际采样的节点增加成功/失败计数，未采样不算失败；过期证据不授权切换；迟到旧结果不覆盖新的复核失败。
- 切换候选明确排除当前入口，并在写操作队列外再次即时验证；进入队列后再次验证状态和决策，避免慢备用阻塞本地开关恢复。
- 手动首选、配置顺序、连续失败阈值、恢复稳定窗口和切回冷却保持不变。Direct 模式清空连续证据并暂停节点决策。全部失败仍不切到直连。
- 独立当前通道与备用通道合并完整、有时间边界的全失败证据（包括只有一个节点的组），供整体链路恢复判定。

## 保留的边界

整体链路 HTTPS 检查仍采用正常 60 秒、异常 5 秒复核；只负责最后手段的有限重载。它不再负责 Windows 开关恢复，未知或不归属本应用的系统设置不授权重载。

没有改变自动故障切换的启用值、节点顺序或用户当前选择。没有打包、推送、发布或覆盖安装。
