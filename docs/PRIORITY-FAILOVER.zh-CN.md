# 配置驱动的故障切换（mxh.7 起）

## 图形界面（mxh.8 起）

在设置首页点击与“应用、核心、远程控制”并列的 **自动故障切换** 入口，进入独立详情页；顶部返回按钮可回到设置首页。详情页中选择目标分组、启用自定义顺序后拖拽节点，或使用上下按钮调整；可以移除不想参与的节点，再从下拉列表加入。未启用自定义顺序时，自动跟随组内排列。

高级参数默认折叠，时间以秒显示，保存时转换为配置文件的毫秒单位。面板显示当前运行节点、当前首选、自动监测／等待首选恢复／Direct 暂停状态及本次应用运行中的最近自动切换。

**保存配置不会重载代理**。保存后可稍后处理，或点击“重载代理应用”并确认短暂断连。代理未运行时不能通过此按钮隐式启动，下次正常启动会读取保存的设置。文件或当前配置在其他位置改变时，先刷新再保存，避免覆盖外部修改。

GUI 与下方文件使用同一份配置；首次打开面板也会创建默认配置文件。旧版桌面宿主或纯 Web 远程控制页不显示此本地设置面板。

应用不再识别 DMIT、VMISS 或 MoeCloud 前缀，也不再强制服务商优先级。

入口列表从应用当前选中的代理配置动态读取，不按分组名称或 `Entry` 后缀匹配。只有非空且所有成员均为实际代理节点的 selector 才可选；引用其他分组或包含 direct、block、DNS、urltest、缺失成员的业务、汇总或混合组均排除。界面、保存校验、运行时探针及缓存恢复共用这一规则。此规则基于配置结构，不推断名称的业务含义；请继续遵守业务组引用代理组的分层设计。

首次创建的 `group` 为空，需在界面明确选择后保存；未选择时不监测任何组，也不妨碍正常启动代理。已有选择和排序不会被覆盖。已保存组被删除、改名或变成混合组时会在界面提示重新选择，运行时不为其创建探针，也不会自动改选其他组。示例中的组名仅为示例，不是应用默认值。

首次启动代理时，应用在自己的数据目录创建 `priority-failover.json`。默认安装通常位于 `C:\ProgramData\mxh-route\priority-failover.json`；自定义数据目录时跟随实际位置。不会覆盖已有文件。它不是 `priority-runtime.json`，也不是 sing-box 权威配置的一部分。

完整示例见 [priority-failover.example.json](priority-failover.example.json)。保存修改后，重新关开代理或重载配置生效，无需重新发布安装包。仅退出并重开应用不保证重新载入已运行核心的探测入口；配置不匹配时不会复用旧探测缓存。

## 常用操作

- **按组内顺序切换**：保持 `order: []`，调整目标 selector 的 `outbounds` 排列并让应用重新载入该配置。第一个可参与节点为最高优先级。当前组保持 DMIT → VMISS → Moe 排列，就继续沿用该顺序。
- **独立指定顺序**：`order` 填精确节点 tag，例如 `["备用入口", "主入口"]`。只使用此列表中的节点，未列出的组成员不参与自动切换；列表成员必须属于目标组。
- **换分组**：修改 `group`，必须与配置中的 selector 名称完全一致。当前支持一个受监测组；缺少该组或没有可用候选时不启用监测，策略日志会记录空候选列表。
- **新增服务商**：把新代理节点加入目标组；空 `order` 会自动采用新组顺序，显式 `order` 则需一并添加名称。
- **关闭功能**：设置 `enabled: false`，重新加载后不再创建自动切换探针入口。

## 参数

| 参数 | 默认值 | 作用 |
|---|---:|---|
| `failureRounds` | 3 | 当前节点连续失败多少轮才考虑切换 |
| `backupSuccessRounds` | 2 | 备用节点需要连续成功的轮数 |
| `recoverySuccessRounds` | 3 | 首选恢复所需的连续成功轮数 |
| `recoveryStableMs` | 120000 | 切回前连续稳定时间，毫秒 |
| `failbackCooldownMs` | 60000 | 切回冷却时间，毫秒；当前备用也坏掉时仍可故障切换 |
| `probeTimeoutMs` | 8000 | 每个 HTTPS 探测超时，毫秒 |
| `healthyIntervalMs` | 30000 | 全部候选正常时，两轮之间等待时间 |
| `failureIntervalMs` | 10000 | 存在不可用候选时的常规轮间等待时间；当前节点初次失败后的连续复核除外 |

当前节点第一次探测失败后，下一轮会在上一轮完成约 1 秒后开始，连续复核直到达到 `failureRounds` 或当前节点恢复。每轮仍需三个 HTTPS 目标中至少两个成功才算可用，备用节点仍需达到 `backupSuccessRounds`；若达到失败轮数却没有可用备用，则退回 `failureIntervalMs`，避免持续高频探测。这个 1 秒是轮间等待，不包括各候选节点的探测耗时。

轮数允许 1–20；稳定和冷却时间允许 10 秒–1 小时；探测超时允许 1–60 秒；常规轮间等待允许 5 秒–10 分钟。轮询唤醒可能额外增加约 1 秒；串行候选探测耗时也计入实际检测延迟。睡眠或长时间断采样不会被算作持续恢复。

仍只选择真正的代理节点，不将 DIRECT、block、DNS 出站或嵌套选择组作为自动备用。每轮三个 HTTPS 目标中至少两个成功才算可用；单个目标失败、慢但成功的请求不会直接触发切换。全部不可用时保持当前选择，不自动直连。

手动选中参与自动切换的节点会把它设为**当前首选**，而不是暂停监测。当前首选故障时按配置顺序选择健康备用；它连续稳定恢复后再切回。手动首选写入运行快照和健康日志，即使改选恰好发生在一轮探测中也会记录；自动切换不会覆盖它，自动重载也会保留它。

重载代理或重启桌面程序时，只要当前代理配置和分组仍匹配，就继续使用保存的手动首选。旧版只保存暂停状态的运行快照会迁移为当前已选入口。若手动选中的节点已从自定义顺序移除，它没有独立探针，界面会提示不受自动切换监测；请把它重新加入顺序。健康守护在这种情况下可以执行整体代理重载，不会无限让步给不能监测当前节点的切换器。

配置文件错误会明确报错，不会默默恢复成旧的固定服务商顺序。桌面应用需保持运行（可留在托盘）。日志规则与 mxh.6 相同。
