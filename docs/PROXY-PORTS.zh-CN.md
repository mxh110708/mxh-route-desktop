# 本地代理端口

入口为“设置 → 端口设置”，沿用现有设置列表、输入框、开关和主题变量。

- 混合代理端口支持 HTTP 和 SOCKS，保持启用，Windows 系统代理使用此端口。
- 独立 SOCKS、HTTP 端口按需启用；不开启时不会新增监听。
- 初始值来自当前选中配置。端口更改保存在该配置的 `inbounds`，不是全局覆盖。
- 新增入站只监听本机回环地址；已有入站的监听地址、标签和认证信息保持不变。
- 端口必须为 1–65535 的整数，启用的代理端口不得重复。保存前检查配置、其他入站及实际 TCP 端口占用。
- 对含多个同类型代理入站的高级配置，界面不擅自改写，请在配置编辑器中调整。

代理停止时，保存不会启动服务，下次启动生效。代理运行时显示“保存并重载”，会短暂重载代理；启动新配置失败时尝试恢复原配置和原服务。若恢复也失败，明确返回错误，不显示保存成功。

重载沿用服务操作队列和配置操作队列。期间暂停本地代理守护观察，并核对选中配置、文件修订和用户操作序号，避免与自动恢复、配置切换或手动停止冲突。系统代理地址和健康检查由新的混合入站端口计算。端口专用重载保留手动选择的故障切换首选入口；停止时的端口修改也保留首选查找信息，但不把旧探测监听当作当前运行态恢复。

远程配置更新或重新导入会读取新的原生入站端口，不会另加一层隐藏的全局端口覆盖。此功能不修改服务器端口，也不修改 Clash 的端口或权威配置。

验证入口：`pnpm test:proxy-ports`、`pnpm typecheck`，以及 dashboard 的 `lint`、`lint:css`。
